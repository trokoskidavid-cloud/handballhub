# 🤾 HandballHub – ракометна лига, статистика и прогнози

Динамичка веб-апликација (MERN: **MongoDB, Express, React, Node.js**) за ракометната **Супер лига** и **EHF Лигата на шампиони**:
распоред и резултати, табела што се пресметува автоматски, статистика на играчите (голови, шутови, одбрани, исклучувања)
и **игра со прогнози** – навивачите го погодуваат резултатот пред натпреварот и собираат поени на ранг-листа.
Податоците за професионални ракометари се збогатуваат од надворешниот извор **TheSportsDB API**.

**Изработил:** Metodij Rizoski · **Професор:** Наташа Табаковска

> 🌐 Продукциска верзија: `https://handballhub.onrender.com` *(заменете со вашиот линк по објавување)*
> 📘 REST API документација: `/api/docs/` · OpenAPI спецификација: `/api/swagger.json`

**Правила за поени (деловна логика):** точен победник (или нерешено) – 2 поени · + точна гол-разлика – 1 поен ·
+ точен резултат – 2 поени (најмногу 5). Табела: победа 2 поени, нерешено 1, пораз 0.

## 🗄️ Колекции (MongoDB)

| Колекција | Опис | Зависи од |
|---|---|---|
| **users** | корисници, улога `user`/`admin`, bcrypt лозинка | – |
| **clubs** | клубови (град, лига, сала, грб, externalId) | – |
| **players** | играчи: позиција, број на дрес, рака за шут, висина | **clubs**, users |
| **matches** | натпревари: статус, резултат, коло + вгнездена статистика по играч | **clubs**, **players** |
| **predictions** | прогнози на корисниците (една по натпревар), поени 0–5 | **users**, **matches** |
| **comments** | дискусија за натпревар | **matches**, **users** |
| **activities** | историја на сите активности | users |

Каскадно бришење: натпревар → неговите прогнози и коментари; играч → неговата статистика од натпреварите;
корисник → неговите прогнози и коментари. Клуб со натпревари не може да се избрише (409).

## 🐳 Локално стартување со Docker (препорачано)

Предуслов: инсталиран [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
cd handballhub
docker compose up --build
```

Командата автоматски ја стартува **MongoDB 7** (контејнер `handballhub-mongo`), ја гради апликацијата (`handballhub-app`)
и при прво стартување ја полни базата со иницијални податоци.

| Адреса | Опис |
|---|---|
| http://localhost:3000/ | апликацијата (React SPA) |
| http://localhost:3000/db | бришење / внесување иницијални податоци |
| http://localhost:3000/api/docs/ | Swagger UI документација |
| http://localhost:3000/mockups/ | статичките маски од Дел 1 |

Запирање: `Ctrl+C` па `docker compose down` (со `-v` се брише и базата).

**Тест сметки** (по внесување иницијални податоци):

| Улога | Е-пошта | Лозинка |
|---|---|---|
| Администратор | admin@handballhub.mk | Admin1234 |
| Навивач | ana@handballhub.mk | Navivac123 |
| Навивач | stefan@handballhub.mk | Navivac123 |
| Навивач | ivana@handballhub.mk | Navivac123 |

Иницијалните податоци се пресметуваат во однос на денешниот датум, па секогаш има **одиграни** натпревари
(со статистика и бодирани прогнози) и **закажани** натпревари што може да се прогнозираат. Играчите се измислени.

## 💻 Локално стартување без Docker

Потребно: Node.js 20+ и локален MongoDB на `27017`.

```bash
cp .env.example .env
npm run install:all
npm run seed              # иницијални податоци
npm run dev:server        # API на http://localhost:3000
npm run dev:client        # React (Vite) на http://localhost:5173 (proxy кон /api)
```

## ☁️ Објавување во облак

**База – MongoDB Atlas**: бесплатен M0 кластер → *Database Access* (корисник) → *Network Access* `0.0.0.0/0` →
connection string `mongodb+srv://<user>:<pass>@<cluster>.mongodb.net/handballhub`.

**Апликација – Render.com** (Docker): качете го проектот на GitHub → Render → *New → Blueprint* (се користи `render.yaml`)
→ во *Environment* поставете `MONGODB_ATLAS_URI`. Кога `NODE_ENV=production`, апликацијата автоматски ја користи Atlas базата.

## 🔌 REST API (преглед)

| Метод | Рута | Пристап | Опис |
|---|---|---|---|
| POST | /api/auth/register · /api/auth/login | гостин | регистрација (+ е-пошта) / најава → JWT |

| GET | /api/matches/:id | сите | детали + резиме на прогнозите |
| POST · PUT · DELETE | /api/matches(/:id) | админ | нов / измена / бришење (каскадно) |
| PUT | /api/matches/:id/result | админ | резултат + статистика → бодирање на прогнозите + е-пошта |
| GET · POST | /api/matches/:id/comments | сите / корисник | дискусија (+ е-пошта до прогнозерите) |
| PUT · DELETE | /api/comments/:id | автор / админ | |
| GET · POST | /api/predictions | сите / корисник | прогнози (една по натпревар, само пред почетокот) |
| PUT · DELETE | /api/predictions/:id | автор (пред натпреварот) / админ | |
| GET | /api/predictions/leaderboard(.csv) | сите | ранг-листа · CSV извештај |
| GET | /api/standings(.csv)?competition= | сите | табела · CSV извештај |
| GET · POST | /api/players | сите / корисник | листа со пресметана статистика, филтри, страничење |
| GET | /api/players/:id(/stats) | сите | детали · статистика по натпревар |
| PUT · DELETE | /api/players/:id | автор, админ / админ | |
| GET · POST · PUT · DELETE | /api/clubs(/:id) | сите / админ | клубови (+ место во табелата) |
| GET · PUT · DELETE | /api/users(/:id) | админ / сопственик | корисници и улоги |
| GET | /api/activities | корисник | историја (админ ги гледа сите) |
| GET | /api/stats/overview | сите | податоци за графиконите |

Статусни кодови: `200, 201, 204, 400, 401, 403, 404, 409, 502`. Грешките имаат облик `{ status, message, errors? }`.

## ✅ Дозволени вредности за внесување

Интегритетот се проверува на три нивоа: **клиент** (`client/src/utils/validators.js`), **апликација**
(`server/middleware/validate.js`) и **шема** (Mongoose модели).

| Поле | Правило |
|---|---|
| Корисничко име | `^[a-zA-Z0-9._]{3,20}$`, уникатно |
| Е-пошта | `^[^\s@]+@[^\s@]+\.[a-zA-Z]{2,}$`, уникатна |
| Лозинка | `^(?=.*[A-Za-z])(?=.*\d).{8,64}$` |
| Име / презиме | `^[\p{L}][\p{L}\s.'-]{1,49}$` (вкл. кирилица) |
| Датум на раѓање (играч) | возраст 15–45 години |
| Позиција | `GK, LW, LB, CB, RB, RW, PV` (голман, крила, бекови, пивот) |
| Број на дрес | цел број 1–99 |
| Рака за шут | `right, left` |
| Висина | 160–220 cm |
| Клуб: име / град / година | уникатно име, букви, 1900 – тековна година |
| Натпревар | различни клубови, статус `scheduled / finished`, резултат 0–70, коло 1–50 |
| Статистика по играч | голови 0–25 (≤ шутови), шутови 0–40, асистенции 0–20, одбрани 0–40, исклучувања 0–3; само играчи од двата клуба |
| Прогноза | цели броеви 0–70, белешка до 200 знаци, една по корисник и натпревар, само пред почетокот |
| Коментар | 2–500 знаци |
| URL | `^https?://\S+$` |

## ✉️ Е-пошта

Без SMTP поставки пораките само се логираат во конзолата. За вистинско праќање поставете `SMTP_HOST`, `SMTP_PORT`,
`SMTP_USER`, `SMTP_PASS` (пр. Gmail App Password, Brevo, Mailtrap). Се праќа: е-пошта за добредојде, освоени поени
по завршен натпревар, нов коментар на натпревар што си го прогнозирал.
